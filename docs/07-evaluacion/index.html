CríticaS1.0✅ RESUELTO — dump.sql versionado expone hashes de contraseñas; admin y operativo compartían hash y la clave era "password"▶

El dump completo de la BD se commiteaba al repo con la tabla users y sus hashes bcrypt reales. Cualquiera con acceso al repo tenía las llaves; con "password" ni hacía falta crackear.

CríticaS2.0API: alumnos, pagos, liquidaciones y clases sin control de rol▶

Todo eso está bajo auth:sanctum a secas. Un token de PROFESOR u OPERATIVO puede crear/borrar alumnos, liquidaciones y disparar pagos por la API — cosas que en la web están bajo ensure.admin. Escalada de privilegios.

  • SS2.2Si la API no se consume, deshabilitarla entera hasta que haya un consumidor y se diseñen sus permisos.

CríticaD1.0El UNIQUE de alumno_planes rompe el 2º cambio de plan (bomba latente)▶

activo es NOT NULL y hay UNIQUE(alumno_id, activo). Al cerrar planes con activo=0, un alumno puede cambiar de plan una sola vez: el segundo cambio da violación de constraint → error 500. Hoy no estalló porque nadie cambió dos veces.

migration create_alumno_planes:24 · AlumnoPlan.php:33-40

  • SD1.1 ⭐Hacer activo nullable y guardar NULL (no 0) en los cerrados; MySQL permite múltiples NULL, el UNIQUE sigue garantizando un solo activo. Migrar los 0 a NULL.
  • SD1.2Quitar el UNIQUE de la BD y enforcar en aplicación (el boot ya lo hace).
  • SD1.3Índice único parcial emulado con columna generada (más complejo).
AltaD2.0referencia_tipo es string libre con valores inconsistentes para lo mismo▶

El servicio marca el reflejo de caja como CAJA_OPERATIVA pero el seeder usó MOVIMIENTO_OPERATIVO para lo mismo. Ya causó el bug de movimientos duplicados en el historial.

cashflow_movimientos.referencia_tipo

  • SD2.1 ⭐Constantes/enum en el modelo y usarlas en todos lados; normalizar los datos existentes.
  • SD2.2Al menos documentar el conjunto válido y corregir el seeder.
AltaD3.0Liquidación acopla profesor↔subrubro por nombre exacto▶

El pago de liquidación busca un subrubro cuyo nombre es "Deporte-Nombre Apellido". Si el nombre cambia o el subrubro no existe, falla con error genérico sin aviso.

MediaD4.0Columna muerta pagos.forma_pago_id (con su FK y tabla)▶
